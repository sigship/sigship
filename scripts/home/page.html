04LimitsFig. 4

What a GO doesn't mean.

A GO means these checks found nothing that blocks launch. It does not prove the app is safe.

  1. FR-1

    Pattern checks can miss real problems and flag safe code. Report a false positive

  2. FR-2

    It reads your repo, so it can't see settings you changed only in a dashboard. Use your database provider's own advisor too.

  3. FR-3

    It reads code, not your live site.

Ask for a pilot review when the stakes are high.

05Where it runsFig. 5

It runs where the work happens. Your coding agent, your terminal, your browser, your pull requests.

Your coding agent

Give your agent the check over MCP, with one rule: it is not done while the verdict is NO-GO. Exit 0 is your agent's test for done.

claude mcp add sigship -- npx -y sigship mcp

Your terminal

Check any project, then paste the fixes into your AI tool as one prompt.

npx sigship --prompt

Your browser

A dashboard with the verdict, every finding and the fix prompt. It runs on this computer only and uploads nothing.

npx sigship ui

Pull requests

A GitHub check that fails when a change brings a serious problem back.

npx sigship init

Building in Lovable, Bolt or Replit? Sync to GitHub, then run npx sigship ui on your computer.

07Ready to sailFig. 7

Ships raise a flag before they leave port. Software never did.

In harbour, flag P, the Blue Peter, tells everyone the vessel is about to sail. In Unix, a signal tells a running program something it has to act on. SIGSHIP is both: one clear message that this app is ready to leave port, or that it isn't yet.

  • +
  • SIGTERM
