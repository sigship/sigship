SIGSHIPFeatures

Everything it does. In plain English.

SIGSHIP reads the code your AI tool wrote and tells you, before launch, what will leak, break or cost you money. Then it hands you the fix.

Get started freeSee pricing

Catches the mistakes that cost you.

17 checks, chosen from how AI-built apps actually fail: leaked keys, open databases, fake payments and runaway AI bills. Tap any check to see what goes wrong and how to fix it.

SEV-1 · 8 checks

Blocks launch. Puts your data or money at risk.

  • A live secret is sitting in your code
  • Your .env file is committed
  • A server secret has a browser-visible name
  • Your AI key runs in the browser
  • A database table has no row level security
  • A database policy lets anyone write
  • Your Stripe webhook accepts anything
  • User input may be pasted into a SQL query

SEV-2 · 3 checks

Blocks launch. Makes abuse easy.

  • Your AI route has no spending brake
  • Admin access is decided in the browser
  • Raw HTML goes straight onto the page

SEV-3 · 6 checks

Worth fixing. Blocks only in strict mode.

  • Any website can call your API
  • A secret may be going to your logs
  • One crash takes down the whole screen
  • You will hear about errors from your users
  • Nothing checks that a change did not break login
  • Your deploys are not repeatable

Fixes with the AI tool you already use.

Every problem comes with a plain fix. Run npx sigship --prompt and you get one prompt with every fix, in order, ready to paste into Lovable, Cursor, Bolt, Replit or Claude Code.

Your AI tool makes the changes. Run SIGSHIP again, and when it says GO, nothing serious is left.

Fix these production problems in order. Change only what each fix needs.
After the fixes, run `npx sigship` again and keep going until it exits 0.
If a fix needs a key rotated or a dashboard changed, stop and tell me what to do.

1. [SEV-1] Your Stripe webhook accepts anything
   Where: src/api/stripe-webhook.ts:3
   Fix: Verify every event with stripe.webhooks.constructEvent, using the raw request body and your webhook signing secret, before you act on it.
2. [SEV-1] A database table has no row level security
   Where: supabase/migrations/001_init.sql:1
   Fix: Add "alter table <name> enable row level security;" in a new migration, then write a policy that limits each row to its owner.
3. [SEV-2] Your AI route has no spending brake
   Where: src/api/chat.ts:2
   Fix: Add a per-user and per-IP rate limit in front of this route, plus a monthly spending cap in your AI provider dashboard.
